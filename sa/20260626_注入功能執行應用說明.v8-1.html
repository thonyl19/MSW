MSW 注入功能執行與應用說明文件 (v8.1)

本文件說明 MSW (Mock Service Worker) 測試面板中「資料注入功能 (Form Injection)」的架構、應用方式與開發配置指南。透過此功能，開發與測試人員可以在免手動打字的情況下，一鍵將模擬的表單資料填入 Vue 頁面組件中。

1. 核心注入模式

MSW 面板目前支援兩種資料注入模式，分別針對「舊頁面相容」與「零改動頁面測試」：

模式 A：直接注入模式 (Direct Injection Mode) - ✨ 推薦使用

  • 特性：主畫面完全不需撰寫任何註冊代碼，由 MockPanel 主動掃描與操縱 DOM。
  • 運作原理：當點擊面板上的注入項目時，MockPanel 會自動掃描常見的 Vue 根節點（如 #app、.app-container 等），透過 el.__vue__ 遞迴尋找其子組件實例中，凡是含有指定屬性名稱（如 form）的對象。
  • 防禦性設計：
    • 深度拷貝：強制使用 _.cloneDeep 隔離資料，防止 Vue 組件雙向綁定修改原始 Mock 數據。
    • 響應性確保：遍歷屬性並使用 Vue.set (或 this.$set) 進行寫入，確保 Vue 2 能監聽到欄位變更並渲染回 UI。

模式 B：訂閱注入模式 (useFormInjection API)

  • 特性：由主頁面組件主動呼叫 API，訂閱全域狀態變更。
  • 適用場景：當頁面有多個獨立的表單實體，或者需要自訂複雜的注入前置/後置邏輯時。
  • 使用方式：

    在頁面組件的 created 或 mounted 週期中註冊：

    import { useFormInjection } from '@/MSW/mock-entry.js';

export default {
    data() {
        return {
            form: {
                LOT: '',
                WO: '',
                QUANTITY: ''
            }
        };
    },
    mounted() {
        // 掛載填表監控，預設會監聽 target: 'form' 並且寫入到 this.form 中
        this.unwatchForm = useFormInjection(this, 'form');
    },
    beforeDestroy() {
        // 銷毀時解除監聽
        if (this.unwatchForm) this.unwatchForm();
    }
};

2. registerMock 注入項目寫法與範例說明

在使用 registerMock 配置面板時，開發人員可以透過以下兩種方式宣告注入項目：

核心概念： 為了將注入按鈕正確地顯示在面板下方的 "Inject" 頁籤，注入項目必須在資料結構中與 target (目標 Vue 組件屬性名) 產生綁定，並遵循固定的類型設計。

方法一：在 controls 陣列中直接宣告 (Actions 按鈕組)

在 controls 中宣告 type: 'actions' 的控制項。此配置會產生一個按鈕群組，點擊時會觸發資料注入：

import { registerMock } from '../mock-entry.js';
import { _form } from './_InspOper.data.js';

registerMock({
  title: '檢驗出站',
  controls: [
    {
      label: '出站檢驗項目資訊',    // UI 顯示的分組標題
      key: 'injectionDemo',       // 唯一的控制項 key
      type: 'actions',            // 必須設定為 'actions' 才會渲染為按鈕群組
      target: 'form',             // ⭐️ 重要：指定要注入的目標屬性名稱 (對應 Vue 實例中的 data 變數)
      list: [
        { 
          text: '檢驗項目資訊-1', 
          type: 'FILL_FORM',      // ⭐️ 必須為 'FILL_FORM'，系統才會判定為資料注入動作
          value: _form.form1      // ⭐️ 注入的資料來源物件，必須使用 value 欄位 (舊版 payload 已廢棄)
        }
      ]
    }
  ]
});
⚠️ 常見踩坑警告 (非常重要)：
  • type 欄位填錯：在 list 子項目中，type 必須設定為 'FILL_FORM'。如果您誤填寫成自定義的字串（例如 type: 'set_model.Setting...' ），注入機制將無法識別該行為。此時按鈕會因為無法被路由到注入處理器，而錯誤地滯留在 "MSW" 基礎控制頁籤下！
  • 欄位名稱錯誤：注入資料必須寫在 value 欄位中。舊版程式所使用的 payload 已不再受支援，寫錯將導致無法讀取資料。

方法二：宣告在 .data.js 的 _inject 物件中 (自動偵測載入 - 推薦)

這是最乾淨、最符合邏輯分離的方式。registerMock 內部會主動偵測與加載 [Page].data.js 中的 _inject 物件，並直接將其映射到 "Inject" 頁籤，連動搜尋與折疊機制。

步驟 1. 在 _InspOper.data.js 中定義：

// ⭐️ 必須使用 export var _inject 導出，名稱不可變更
export var _inject = {
    // 第一層 Key 為注入的目標對象名稱 (例如 Vue data 中的 'form' 或 'queryForm')
    form: {
        // 第二層 Key 為情境名稱 (顯示在 Inject 頁籤的按鈕文字)
        "檢驗項目資訊-1": { 
            Insp_Match: false, 
            NCR_Hold: false, 
            Prod_Grading: false, 
            EdcList: null, 
            WP_IPQC_LOT: null 
        },
        "一般出站設定": { 
            Insp_Match: true, 
            NCR_Hold: false, 
            Prod_Grading: true 
        }
    },
    // 如果同頁面有另一個 target 叫 query
    query: {
        "依批號查詢": {
            LOT_NO: "LOT123456"
        }
    }
};

步驟 2. 在 _InspOper.js 中註冊：

import { registerMock } from '../mock-entry.js';
import { pageHandlers } from './_InspOper.js';

registerMock({
  title: '檢驗出站',
  controls: [
    // 這裡只需要定義一般的 API 攔截開關與 Select，完全不用寫 actions 注入按鈕
  ],
  // 系統會自動解析同目錄下的 _InspOper.data.js 並加載其 _inject 到 Inject 頁籤中！
  handlers: pageHandlers
});

3. 資料與目錄規範 (.Data.js)

為了落實資料與邏輯分離，系統採用 [Page].js ↔ [Page].Data.js 1:1 自動對應慣例。

目錄結構範例

src/pages/
├── _MultOper_MPI.js       # Mock 攔截與 UI 設定檔
├── _MultOper_MPI.data.js  # 靜態模擬數據與注入情境宣告 (1:1 對應)

4. MockPanel 使用指南 (UI 操作)

  • 開啟面板：點擊網頁右下角的 🧪 浮動按鈕展開測試面板。
  • 切換分頁：切換至下方 Inject 頁籤。
  • 多來源切換：若當前頁面載入了多個 Mock 來源，面板頂部會自動出現 Radio Button 或 Select 選單，切換後下方的注入項目會同步更新。
  • 搜尋過濾：在搜尋欄輸入關鍵字（例如「一階」），系統會即時篩選情境名稱與 Target，並自動展開對應的折疊區塊。
  • 執行注入：點擊任何一項情境（如 📥 一階流程案例），資料會即時注入並填入畫面表單中。
  • 快照持久化 (Catch)：點擊面板右上角的 💾 (Save Catch) 按鈕，可將當前的 API 開關、延遲、選項以及最後一次注入的狀態儲存於 sessionStorage，重整網頁後會自動還原。

5. 常見問題與偵錯 (Troubleshooting)

Q：為什麼我的注入按鈕出現在 "MSW" 控制分頁，而不是 "Inject" 分頁？
答： 請檢查 controls 內 list 陣列項目的 type。如果您寫了自訂字串，或者是舊版未使用的設定，MockPanel 會因為判定不是標準的 FILL_FORM 注入動作，而將按鈕渲染在一般控制項區塊（即 MSW 分頁）。請改回 type: 'FILL_FORM'，或改將資料宣告在 .data.js 的 _inject 中。
Q：點擊注入按鈕後，畫面上表單沒有任何變化？
1. 檢查主畫面 Vue 元件的 data 命名：直接注入模式預設尋找 form 屬性。若您的頁面變數名為 queryForm 或 submitData，請確認 .Data.js 的 _inject 宣告中是否已正確對應。
2. 檢查 Console 警告：如果命名不符或元件中不存在該變數，Console 會輸出黃色告警：[MSW Injection Error] 找不到對象屬性 'xxxx' 在目前組件實體中。 請根據此警告修正 target 命名。
Q：有些輸入框在注入後無法手動編輯，或編輯時會影響到 Mock 原始數據？
此問題已由 _.cloneDeep 防禦性機制 徹底解決。注入時會切斷物件參照，若仍有異常，請確認頁面中是否有使用自訂的資料共享。
